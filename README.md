# G-Tun

**A lightweight, authenticated, multi-protocol tunnel written in Go.**

![Go](https://img.shields.io/badge/Go-1.23+-00ADD8?style=for-the-badge&logo=go)
![Platform](https://img.shields.io/badge/Platform-Linux-informational?style=for-the-badge&logo=linux)

</div>

G-Tun connects a **client** (the machine your users connect to) with a **server** (the machine that runs the
destination service, typically an Xray inbound). Traffic crosses the link over one of nine transports, and every
connection is authenticated with a shared secret before a single byte reaches the destination.

```
 application ──► g-tun-client ═══ tunnel (tcp | ws | wss | quic | kcp | ...) ═══► g-tun-server ──► Xray / target
                      │                                                                  ▲
                      └─────── control channel (authenticated, announces protocol) ──────┘
```

## Features

| | |
| :-- | :-- |
| **9 transports** | `tcp`, `udp`, `ws`, `wss`, `tcpmux`, `wsmux`, `wssmux`, `utcpmux` (KCP), `quic` |
| **Multiplexing** | smux over TCP, WebSocket or KCP, or native QUIC streams, so many connections share one tunnel |
| **Authenticated everywhere** | mutual HMAC-SHA256 handshake on every connection; tagged UDP datagrams |
| **Certificate pinning** | TLS transports trust only the exact certificate generated by your server |
| **Self-healing** | the client reconnects with exponential backoff and replaces dead sessions transparently |
| **One-command setup** | installer, `systemd` services and a control panel (`g-tun`) |

## Install

Ubuntu 20.04 / 22.04 / 24.04 (and other Debian-based systems), amd64 or arm64, as root:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mahdi-1991/G-tun/main/install.sh)
```

Run it on the **server** first and choose *Server*. It prints a token and a certificate. Then run it on the
**client**, choose *Client* and paste both.

Manage a running installation with the control panel:

```bash
g-tun
```

### Updating

Use *Update* in the panel, or run `bash /root/G-tun-Project/install.sh --update`. Update both sides: a
new server does not talk to an old client. Upgrading from 1.x? Re-run the installer once (see the
[changelog](CHANGELOG.md)).

## Protocols

| Protocol | Carrier | Notes |
| :-- | :-- | :-- |
| `tcp` | TCP | simplest; one tunnel connection per stream |
| `ws` / `wss` | WebSocket (plain / TLS) | passes HTTP-aware middleboxes; `wss` is encrypted |
| `tcpmux` / `wsmux` / `wssmux` | smux over TCP / WS / WSS | one connection carries many streams |
| `utcpmux` | smux over KCP (UDP) | AES-256 encrypted, forward error correction, good on lossy links |
| `quic` | QUIC (UDP) | encrypted, multiplexed, resists packet loss; recommended |
| `udp` | UDP datagrams | relays datagram to datagram; the target must be a **UDP** service |

Only the `wss`, `wssmux` and `quic` transports are encrypted by TLS, and `utcpmux` by AES. The other protocols
are authenticated but not encrypted, which is fine when the carried traffic is already encrypted (for example an
Xray VLESS/VMess/Trojan inbound).

## Configuration

Files live in `/etc/g-tun/` and are created by the installer.

`server_config.json`

| Key | Meaning |
| :-- | :-- |
| `control_port` | TCP port clients use to authenticate and learn the transport |
| `data_port` | port of the transport itself (TCP, or UDP for `udp`, `utcpmux`, `quic`) |
| `protocol` | one of the protocols above |
| `xray_inbound_address` | `host:port` the traffic is relayed to |
| `token` | shared secret, at least 16 characters (the installer generates 64 hex characters) |
| `tls_cert_path`, `tls_key_path` | certificate and key for `wss`, `wssmux` and `quic` |
| `kcp_config` | KCP tuning, announced to clients |

`client_config.json`

| Key | Meaning |
| :-- | :-- |
| `control_server_address` | `server-ip:control_port` |
| `remote_server_ip` | server address used for the data port |
| `local_listen_port` | local `host:port` applications connect to |
| `token` | the server's token |
| `tls_cert_path` | optional; the pinned server certificate (default: `cert.pem` next to the config) |

Both binaries accept `-config <file>`, `-check` (validate and exit), `-debug` and `-version`.

## Security model

- The token never crosses the network. Each connection runs a three-message handshake in which both sides prove
  they know it, using fresh nonces, so recorded handshakes cannot be replayed.
- Nothing is relayed to the target before the handshake succeeds, so scanning the data port reaches nothing.
- The control message that selects the protocol is MAC-protected and bound to the session.
- The generated certificate is pinned by the client, so TLS cannot be intercepted with another certificate.
- Keep the token secret. Anyone who has it can use your tunnel.

Not covered: the authenticated-but-unencrypted protocols do not hide your traffic from an observer on the path,
and the protocol can be recognised by traffic analysis. G-Tun is a transport, not an anonymity tool.

## Development

```bash
make            # gofmt check, go vet, tests (with -race) and build into ./bin
make test
go run ./cmd/g-tun-gencert -cert cert.pem -key key.pem
```

```
cmd/            g-tun-server, g-tun-client, g-tun-gencert
internal/
  auth/         handshake and datagram authentication
  config/       configuration files and validation
  control/      the control message
  transport/    the nine transports (server and client sides)
  server/       control listener + data listener
  client/       control connection, transport supervisor
  netutil/      accept loop, bidirectional relay
  tlsutil/      certificate generation and pinning
```

Run `go mod tidy` once after cloning if Go reports that `go.mod` needs updating.
